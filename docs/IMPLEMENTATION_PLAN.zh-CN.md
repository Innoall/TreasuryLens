# TreasuryLens 实施计划

范围：项目代码、查询界面、测试、实验脚本、运行与安全文档。暂不制作 Demo 视频、PPT、pre 或最终课程报告。当前不发布 GitHub 仓库，不使用真实资金或付费服务。

## 阶段与完成条件

1. 环境与技术验证：固定 Lyquor LDK v0.8.3、Rust 1.99、Foundry v1.7.1；本机四节点网络启动，完成真实认证调用。
2. 核心数据链路：本地部署 ERC-20、生成已知交易、独立校验历史转出总额；地址、区块、金额与日志均严格验证。
3. 多节点核验：同一查询与快照的 3/4 节点一致；使用 LDK two-phase oracle certification；仅认证提交可以写入结果；重复查询幂等。
4. 产品闭环：查询界面连接真实 Lyquid HTTP 接口，展示确认/失败、快照、支持节点与证书签名者；下游 Lyquid 读取已确认结果进行预算判断。
5. 测试与评估：正常、空结果、异常数据、过期快照、重复身份、越权、无足够有效响应和重试；保存真实测试与实验结果，区分纯逻辑测试与 devnet 集成。
6. 可复现交付：版本锁定、启动/停止/部署/造数/测试指令、干净环境要求、架构与信任假设、AI 和外部代码来源记录。

## 开发原则

- 先打通关键技术路径，再完善功能；平台限制会写明，失败不伪装成成功。
- 固定 4 个授权节点、门槛 3；用户不能通过请求修改门槛。
- 统计标准 ERC-20 Transfer 日志中的总转出；整数最小单位，不等同会计支出或净流出。
- 固定区块范围并绑定终点块哈希；读取前后确认相同快照。链 ID、地址、范围和规则版本均进入查询身份。
- 多节点公用一个本地 RPC 用于可复现实验，不能抵御共同数据源错误；不宣称密码学证明或无信任系统。
- 测试故障控制用显式 test-controls 编译特性隔离；正式构建默认不含故障接口。

阶段 1–6 已实现首版并完成以下自动验证：33 项 Rust 测试、9 项正式网络集成检查、14 项测试构建故障检查、4 项真实跨 Lyquid 预算检查。运行记录见 evaluation/observed/。从停止旧网络后的干净链启动流程已跑通。

尚待人工完成：浏览器视觉与交互检查、组外同学实际试用、团队成员理解与贡献确认。当前环境禁用了本地浏览器自动控制，因此没有将视觉检查标为完成。真实节点进程退出或网络丢包的服务端超时仍受 LDK 限制，详见 docs/SECURITY.md；故障注入的“不可用”表示签名的源数据读取失败。

本机当前正式查询页：http://127.0.0.1:8080。重启可运行 bash scripts/start.sh；已有网络占用端口时，脚本会提示并退出，不会杀其他进程。
