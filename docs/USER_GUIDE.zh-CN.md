# TreasuryLens 使用指南

本应用查询一个标准 ERC-20 代币、一个金库和一段闭区间历史中的总转出事件。包括金库向自身转账和零金额事件；只入账的交易不计入。它不是余额查询、会计支出判定或真实资产支付工具。

## 启动与第一次查询

在项目目录执行 `bash scripts/start.sh`，保持该进程运行，然后打开 `http://127.0.0.1:8080`。首次启动会下载固定版本依赖，后续复用。已有网络占用所需端口时不会自动终止其他进程。

1. 在 Overview 工作区加载默认测试数据，核对代币、金库和区块范围。
2. 发起核验。提交请求并不代表结果已确认，页面会等待共享状态中的实际记录。
3. 默认数据应得到 7,500,000 个最小单位、3 条转出事件。测试代币的小数位为 6，即 7.5 枚测试代币。
4. 查看观察支持节点和认证签名节点。二者可能不同，代表观察匹配与批准最终调用两种职责。

## 从总额追溯到逐笔记录

选择已确认查询后，在 Evidence 工作区运行数据重放。服务重新读取固定查询快照的数据，重新计算总额、事件数量和规范化事件摘要，并与保留的已认证摘要逐项核对。

只有重放匹配时，账本和分布才应被解释为这个已认证摘要的内容。可以搜索收款地址/交易、筛选收款人、排序，查看按区块与收款人的分布。

重放本身是当前服务对来源 RPC 的读取和内容核对，并未形成一张新的委员会证书。如果来源出现一致错误或遗漏，匹配仍不能证明历史绝对完整。

## 保存与验证证据

从匹配的重放结果导出证据 JSON。文件包含查询、摘要和原始日志，用来复现计算；任何人都可以修改文件中的文字，因此导入后的“内容有效”只表示文件内部满足计算规则。

导入文件后执行验证。如果修改金额、删除/增加事件、改变绑定的快照或摘要，核对通常会失败。若攻击者同时重算所有内容，文件仍可能内部一致。因此导入的内容不自动进入已认证历史，不表示签名验证通过，也不能取代从可信部署读取原始记录。

断开应用服务后仍可使用原生 CLI 重算文件内容：

```sh
source scripts/env.sh
cargo run --locked -p treasurylens-core --bin verify-evidence < 证据文件.json
```

## 比较与预算

Compare 工作区比较两条兼容记录的总额差异。只有链、代币、金库与规则相同才有可比性；区块区间相交时不能把两个总额相加当作无重叠累计。

预算试算在浏览器使用整数计算，不转移资产，也不会改变已认证历史。独立 Budget Monitor 的真实跨 Lyquid 检查使用交易调用并保存结果，具体命令和自动验证见 README。

## 快照重新检查

对选定的已确认查询执行重新检查，页面读取当前来源 RPC 中同一高度的区块哈希，与原快照比较。匹配表示该来源目前仍报告同一哈希；变化表示旧查询不再对应它当前报告的快照。该检查不会删除或修改原始认证记录。

两块确认深度只是本地试验的启发式规则，不是不可逆最终性；多个节点共用一个 RPC 也不是多来源证明。

## Integrity Lab 与保存查询

Integrity Lab 是浏览器中的确定性模拟。改变四个节点的状态，可以观察单节点、只比较数值和绑定快照的门槛规则的差异。它不会修改运行中的节点，不是真实故障实验测量。

浏览器保存的查询预设仅存在本机浏览器存储中，不属于链上状态或团队共享配置。不要把浏览器书签的存在理解为该查询已通过核验。

## 异常与排查

- 无连接：检查启动进程以及 `/api/status`，不要将断开状态当作零转账。
- 未凑齐 3 个匹配结果：查询不确认；不要手动放宽门槛来获得期望答案。
- 超时：当前服务请求可能仍在处理中；刷新确认历史检查实际状态。真实丢包时服务端超时受 LDK 限制。
- 记录不存在：最多保留最新 200 条新查询，旧记录可能被淘汰；必要时重新查询。
- 重启后地址变化：默认本地网络重建，重新造数与部署；以前文件中的地址/快照不是当前链的记录。

自动测试不能替代组外同学真实试用。组外测试应让对方从 README 独立操作，记录实际遇到的问题和改进，不使用虚构反馈。
