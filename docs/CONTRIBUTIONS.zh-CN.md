# 功能贡献与研究边界

本文描述拟作为课程项目贡献的具体机制，不声称其在学术或商业系统中首次出现。选用 Lyquor 内建证书和节点通信本身属于平台使用；项目贡献需由相对基线的设计、实现和实验支撑。

## C1：查询与快照绑定的内容一致性

单节点返回一个数值无法抵御该节点错误；只对总额/数量投票又可能把不同快照的同值结果混合。TreasuryLens 将链、合约、金库、区块范围、终点块哈希和规则版本绑定到查询身份，将逐笔已验证日志绑定到规范化摘要，并要求不同授权节点对完整摘要形成 3/4 匹配。

验证方式：核心单元测试；单节点错误/过期数据/多个错误结果的真实本地四节点测试；独立标注的合成输入消融对照。

限制：证书证明配置委员会批准了调用；无法排除共同 RPC 错误、遗漏、节点串通或恶意标准形状日志。

## C2：证据内容重放与可解释核验

一个总额难以被用户检查。应用把总额进一步映射到逐笔事件、收款人和区块分布。下钻前重新读取历史数据，并要求总额、事件数量、查询身份、快照和日志摘要与保留认证记录完全相符。聚合使用 uint256 整数和加宽算术计算份额，避免大额数据浮点精度损失。

验证方式：重放匹配、金额/日志元数据篡改、重复与冲突日志、空结果、uint256 边界和分组求和的测试。

限制：下钻结果由当前实例重放而来；摘要绑定使其可与原记录核对，但此重放不是新的委员会认证或收据根证明。

## C3：可移植证据及真实性分层

证据包导出查询、已认证摘要的副本和原始事件日志；导入或离线 CLI 可重复解析与摘要计算，检测内容修改。产品将文件内部一致、来源快照现状和部署中已有委员会认证分成明确状态，避免将“上传的 JSON 自洽”误报为“证书已验签”。

验证方式：有效包、金额修改、事件删除、绑定快照变化、不支持版本、超大请求的实际接口检查；离线验证器使用同一严格核心规则。

限制：包不含可独立验证的委员会证书；若全部声明与内容一起被重写，内部一致性校验不能证明来源真实性。

## C4：面向操作的快照复查与安全失败

历史记录保留原始核验事实，另提供当前来源对终点块哈希的复查结果，避免将“历史上保存过”当作“永远有效”。当有效数据不足时不产生确认记录；四个签名响应却无法形成匹配门槛时，显式拒绝而非伪造零值。

验证方式：当前快照哈希检查、未找到记录、读取失败分支、3 有效/1 失败、2 有效/2 失败等。

限制：复查不自动撤销已保存记录；真实网络分区的完成时间未建立硬保证。

## 产品交互支撑

账本筛选、收款人分布、区块时间线、兼容查询比较、精确预算试算、浏览器预设和故障模型实验帮助理解上述机制。界面复杂度本身不是创新证据；只有连接真实数据、准确标注信任边界并完成测试的交互才计入项目实现。
